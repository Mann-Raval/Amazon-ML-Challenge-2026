# Amazon ML 2026 — Business Entity Resolution

This repository contains our solution for the Amazon ML 2026 Business Entity Resolution competition.

The task is to match each business in **Source 1** with all corresponding businesses in **Source 2** and **Source 3**. The records do not share a common ID. Names and addresses may contain spelling mistakes, abbreviations, transliteration, punctuation differences, and missing information.

## Important status

The repository contains the complete runnable pipeline and submission structure. The currently generated output files are format-valid placeholders because the training dependencies were unavailable in the original environment. They must be replaced with predictions generated by the trained model before submission.

## How the solution works

1. Normalize business names and addresses.
2. Generate a small set of possible matches using name/address tokens and country.
3. Calculate similarity features for every candidate pair.
4. Train a LightGBM classifier using the labelled training data.
5. Select a decision threshold using the competition's precision-focused macro F0.5 score.
6. Generate the two required TSV files for the test data.

Countries are handled as open string values. No list of countries is hard-coded, so the test-only France records go through the same pipeline.

## Setup and execution

Open a terminal in:

```text
student_resource/code/business_entity_resolution
```

Create an environment and install dependencies:

```bash
python -m venv .venv
```

Windows:

```bash
.venv\Scripts\activate
```

macOS/Linux:

```bash
source .venv/bin/activate
```

Install the pinned packages:

```bash
python -m pip install -r requirements.txt
```

Train the model:

```bash
python -m src.train \
  --train-dir ../../dataset/train \
  --model-out models/model.txt \
  --threshold-out models/threshold.json
```

Generate test predictions:

```bash
python -m src.predict \
  --test-dir ../../dataset/test \
  --model models/model.txt \
  --threshold-file models/threshold.json \
  --output-dir ../../output
```

Validate the output files from the `student_resource` directory:

```bash
python utils/validate_submission.py \
  --matching output/matching_results.tsv \
  --candidate output/candidate_pairs.tsv \
  --test-dir dataset/test
```

The validator must print `PASS` before uploading `matching_results.tsv`.

## What the output files mean

`matching_results.tsv` is the scored submission. It contains one row for every test Source-1 entity and a comma-separated list of matching Source-2/Source-3 IDs. An empty list means the model predicts no match.

`candidate_pairs.tsv` records the possible Source-2/Source-3 matches considered before classification. Every final match should also appear in this file.

## Data and GitHub

The supplied TSV files are very large and should not normally be committed to GitHub. GitHub rejects individual files larger than 100 MB, and the complete dataset is much larger than that. Share the dataset through the competition download or an approved team storage location, then place it under `student_resource/dataset/` locally.

Do not commit trained model files, virtual environments, caches, or generated outputs until the team agrees on the final predictions. The included `.gitignore` lists these files.

## GitHub workflow for teammates

One teammate creates the repository and pushes the code:

```bash
git init
git add README.md .gitignore student_resource/code student_resource/utils student_resource/Documentation_template.md
git commit -m "Add entity resolution competition pipeline"
git branch -M main
git remote add origin https://github.com/<TEAM>/<REPOSITORY>.git
git push -u origin main
```

Other teammates clone it with:

```bash
git clone https://github.com/<TEAM>/<REPOSITORY>.git
```

They then download or copy the competition dataset into `student_resource/dataset/`, follow the setup commands above, and create a branch for changes:

```bash
git checkout -b improve-matching
```
